# Contributing

1. Start from `main` on a card-specific branch.
2. Claim one eligible SKCapstone card before editing.
3. Keep runtime changes separate from terminology and documentation changes.
4. Run the commands in `SOP.md` section 4, including schema and example tests.
5. Open a pull request with exact card, test, rollback, and evidence references.
6. Use a reviewer who did not produce the candidate.

Use conventional, imperative commit subjects. Never commit secrets or rewrite historical evidence to update terminology.
